# Key、计费与重试安全

公开 API 可以代表你的账户执行收费创作任务。接入前应同时保护凭据、积分和任务状态。

[返回首页](../README.md) · [API 摘要](api.md) · [常见问题](faq.md)

## API Key 保管

- 只在[官方 API 文档](https://feilun.ltyfa.top/api-docs)或飞轮应用内创建 Key。
- 创建后立即复制保存，明文只显示一次。
- 使用本地凭据、环境变量或密钥管理服务，不写入源码和 Git。
- 不把完整 Key 发到公开群聊、Issue、截图或日志中。
- 为不同工具使用容易识别的 Key 备注，发现泄露时及时处理对应 Key。
- MCP 配置不填写 Key，先本地 `login`，再让 MCP 复用凭据。

本仓库的示例只使用 `$FEILUN_API_KEY` 或占位符，不应替换为真实 Key 后提交。

## 首次验证保持免费

推荐的首次验证顺序：

```text
health → balance → coach
```

不要为了让 AI 工具“证明接入成功”而自动生成大纲或整篇图片。收费任务应由用户明确确认。

## 收费操作使用幂等键

大纲、整篇出图和单页重出要求 `Idempotency-Key`。一个逻辑任务生成一个稳定键，并把它与请求参数一起保存，便于网络异常后恢复。

### 可以安全重试的情况

- 客户端超时，尚未确认服务端结果。
- 返回 `429 IDEMPOTENCY_IN_PROGRESS`。
- 返回可重试的临时网络错误。

重试时保持原幂等键和原参数，并遵守 `retryAfterSec` 或 `Retry-After`。

### 不要直接重试的情况

- `402 INSUFFICIENT_BALANCE`。
- `409 IDEMPOTENCY_CONFLICT`。
- `409 REVISION_CONFLICT`。
- 长时间状态未知且尚未查询 record 或流水。

这些错误需要先处理余额、参数、版本或对账问题。

## 先查询，再决定是否重新执行

网络中断或超时后：

1. 使用原 record 查询当前状态。
2. 查询积分流水，确认是否已有对应消耗。
3. 使用原幂等键重放或等待结果。
4. 仍无法确认时停止自动重试并寻求支持。

不要通过更换幂等键绕过处理中状态，这可能导致同一业务被重复执行。

## 限流与异步任务

- 免费 coach 按账户限制为每滚动 24 小时 30 次，所有 Key 共享。
- 出图可能另有任务排队或提交中状态。
- `202` 表示异步任务已受理，不表示图片已经全部完成。
- 通过 record 查询进度，不要建立高频无间隔轮询。
- 客户端应为网络异常保留任务标识，而不是反复创建新任务。

## 发布安全

Skill API 的出图完成不等于自动发布到小红书。网页发布流程还涉及账号绑定、发布助手和发布确认。

发布前应检查：

- 文案与图片是否准确、合法并符合平台规范。
- 是否拥有素材与参考内容的使用权。
- 是否选择了正确账号、人设和发布任务。
- 是否理解自动发布免责声明。

飞轮不承诺曝光、互动或收益结果。

## 提交问题时的脱敏要求

在 GitHub Issue 或其他公开渠道反馈时：

- 可以分享错误码、脱敏后的请求步骤和 `doctor` 的非敏感状态。
- 隐藏完整 Key、JWT、账号邮箱、用户稿件和图片地址。
- 不提交数据库、服务器、内部配置或其他用户数据。
